# 艾琳娜的漫游地图｜产品需求文档（PRD）

- 版本：V1.0
- 产品：微信小程序 + Web 内容管理后台
- 项目代号：`elena-travel-map`
- 状态：开发基线，待业务确认
- 日期：2026-11-19

## 1. 产品概述

### 1.1 定位
「艾琳娜的漫游地图」是一个以个人真实旅行经历为数据资产、以跨国路线内容为核心，同时服务旅行者和内容创作者的旅行知识与规划平台。

两类核心价值：
1. **个人旅行知识库**：持续沉淀国家、城市、交通、路线、照片、预算、亲历经验和资料来源。
2. **旅行内容与商品平台**：让用户浏览、搜索、收藏路线，查看亲历经验，购买数字路线资料，并逐步形成自己的行程。

### 1.2 品牌
- 中文名：艾琳娜的漫游地图
- 英文名：ELENA'S TRAVEL MAP
- 品牌主张：把走过的地方变成可复用的路线，把个人经验变成有价值的旅行产品。

## 2. 用户角色

### Traveler（旅行者）
浏览、搜索和筛选路线；查看路线节点、交通、亲历经验及来源；收藏路线；购买数字商品；创建个人行程草稿。

### Creator / Admin（创作者/管理员）
V1.0 由产品所有者本人担任，负责国家、城市、路线、节点、交通、旅行笔记、签证经历、媒体和商品的录入、审核、发布及下架，并管理订单。

### 权限原则
- 游客只能访问已发布内容。
- 登录用户可使用收藏、订单和行程功能。
- 管理写操作必须由服务端鉴权，不能只依赖前端隐藏按钮。

## 3. 产品范围

### P0：首发必需
1. 首页及精选路线。
2. 路线列表、搜索、筛选和详情。
3. 国家、城市、路线、路线节点数据管理。
4. Web 管理后台基础能力。
5. 商品列表、详情、订单创建。
6. 微信登录和微信支付接入。
7. 支付成功后的订单校验与数字文件交付。
8. 内容草稿、审核、发布、下架状态。

### P1：首发后迭代
- 路线收藏。
- 简化版行程规划表。
- 简化版预算记录。
- 出发清单和已购资料入口。

### P2/P3
- P2：AI 行程规划、路线问答、个性化推荐。
- P3：UGC、多创作者入驻、协作与分账。

### 暂不做
实时机票酒店及交通价格、自动判定实时签证政策、AI 自动决定复杂跨国交通、全球导航和路线优化、多人实时协同、多创作者分账。

## 4. 页面与信息架构

小程序底部四个导航：

| 导航 | 页面 | 内容 |
|---|---|---|
| 首页 Home | `home` | 品牌主视觉、精选路线、地区入口、专题、商品推荐 |
| 探索 Explore | `explore` | 路线搜索、筛选、列表及详情入口 |
| 工具 Tools | `tools` | 行程表、预算表、出发清单、已购资料 |
| 我的 Profile | `profile` | 收藏、订单、已购资料、行程草稿、咨询、协议 |

### 首页
品牌栏、跨洲旅行主视觉、精选路线、地区入口、专题入口、数字商品推荐。

### 探索页
筛选维度：地区、建议天数、路线类型（单国/多国/闭合环线/跨国单程）、主题、内容完整度（A/B/C）。

### 路线详情页
展示标题、副标题、路线类型、内容等级、核验状态、建议天数、地区、主题、路线简介、节点顺序、建议停留时间、交通记录、亲历经验、来源及关联商品。

**路线类型规则：**只有首尾确认闭合的路线才标记为 `loop`（闭合环线）；其他多国路线不得仅因经过多个国家而称为环线。

### 工具页
轻量行程规划表、预算记录、出发清单、已购资料。

### 我的页面
用户资料、收藏、订单、已购资料、行程草稿、定制咨询、用户协议、隐私政策和客服入口。

## 5. 核心业务流程

### 内容生产与发布
创建国家/城市 → 创建路线 → 添加有序节点 → 添加交通、经验、媒体和来源 → 保存草稿 → 完整性检查 → 审核 → 发布。内容可下架，历史版本保留。

### 商品购买与文件交付
查看商品 → 服务端创建订单并计算价格 → 服务端创建微信支付单 → 微信异步回调 → 服务端验签、核对金额和订单号 → 幂等更新支付状态 → 用户请求文件 → 服务端校验用户、订单和商品权限 → 返回短时有效下载地址。

**安全要求：**不得仅凭前端支付成功状态发放文件；对象存储文件默认私有，不使用永久公开链接作为交付权限。

### 路线浏览
首页/探索 → 筛选路线 → 路线详情 → 查看节点、交通、亲历记录和来源 → 收藏或进入关联商品。

## 6. 内容质量和数据规则

### 内容等级
- **A级：完整亲历路线**——路线主体、主要节点及关键经验来自本人亲历。
- **B级：部分亲历路线**——部分节点或交通来自亲历，其余信息需标注来源。
- **C级：旅行灵感路线**——研究整理或规划建议，不得包装成完整亲历。

前端必须显示内容等级。内容等级与核验状态是不同维度。

### 核验状态
`unverified` 未核验；`partial` 部分核验；`verified` 已核验。

### 时间敏感信息
- 历史亲历票价必须记录发生日期。
- 当前报价应保存来源和核验时间；未经核验不得标为当前价格。
- 个人签证经历必须与现行官方签证政策分开展示。
- 官方来源保存 URL、核验时间和适用对象。
- 页面注明旅行经历不构成实时政策或服务承诺。

### 路线节点
- 同一城市可在同一路线重复出现。
- 节点顺序由 `sequence` 决定。
- 不设置 `(route_id, city_id)` 唯一约束。
- 节点记录建议停留天数和实际停留天数。

### 初始专题候选
从新疆出发穿越欧亚非、中亚丝路、高加索三国、巴尔干半岛、埃及、阿联酋与阿曼、斯里兰卡。已有历史行程中仍有城市、交通和日期待补字段，发布前必须人工确认，不得自动推断补齐。

## 7. 非功能需求

### 安全
- 用户端与管理端分离鉴权。
- 管理写接口使用 RBAC 或等效权限控制。
- 支付回调验签、金额校验、幂等处理。
- 文件使用私有存储和短时签名 URL。
- 密钥只保存在服务端环境变量。
- 管理操作写审计日志。

### 性能与可维护性
- 首页、路线列表分页。
- 图片使用缩略图和适配尺寸。
- 列表查询建立必要索引。
- API 统一错误结构。
- TypeScript 贯穿小程序、后台和 API。
- 数据库迁移纳入版本控制，关键业务逻辑有自动化测试。

## 8. 技术方案基线

- 微信原生小程序 + TypeScript。
- TDesign Miniprogram（可选）。
- Node.js + TypeScript API。
- PostgreSQL + Prisma ORM。
- React + TypeScript Web 管理后台。
- 图片/PDF/Excel 使用私有对象存储。
- REST API + OpenAPI。
- GitHub 版本管理。

轻量替代方案：评估微信云开发 CloudBase；选型前需核对支付、文件权限、数据库和部署限制。

## 9. 数据分析指标

埋点：首页访问、路线列表访问、筛选使用、路线详情访问、商品详情访问、创建订单、支付成功、文件下载、收藏、创建行程、咨询点击。

观察指标：路线详情访问率、商品点击率、下单转化率、支付成功率、文件交付成功率、内容录入和更新耗时。首发目标值应以真实流量建立基线，不预设虚构转化承诺。

## 10. 验收标准

### P0
- 游客可浏览已发布路线。
- 草稿/下架内容不出现在公开接口。
- 搜索、筛选、分页和详情正确。
- 管理员可创建、编辑、审核、发布路线。
- 商品可展示价格、说明和交付信息。
- 服务端创建订单并发起支付。
- 支付回调验签、金额校验、幂等处理。
- 未支付或非本人订单不能获取文件。
- 已支付用户可获得短时有效下载地址。
- 管理操作可追溯。

### P1
- 用户可收藏/取消收藏。
- 用户可创建行程并添加日期条目。
- 用户可记录预算。
- 用户可查看已购资料。

5. 用户协议、隐私政策和个人信息收集清单需完成。

7. 上线排期受资质、支付接入和平台审核影响，不保证审核通过时间。
